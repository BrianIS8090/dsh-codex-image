# Codex image (GPT Image) для DeepSeek Harness

Локальный плагин: генерация и редактирование изображений моделью **gpt-image-2.5** через CLIProxyAPI с подключённым Codex (`https://spa.brianfox.ru/v1`). Все настройки генерации — на странице плагина.

## Что добавляет

| Где | Что |
| --- | --- |
| Агент | Инструмент `gpt_image_generate` — картинка по текстовому описанию |
| Агент | Инструмент `gpt_image_edit` — правка, перерисовка или объединение изображений из диалога (вложения и прошлые результаты) или файлов рабочей папки |
| Чат | Карточка вызова: промпт, индикатор «рисую…», галерея результатов, ссылка на сохранённый файл, ошибки |
| Плагины → Codex image | Страница настроек, проверка подключения, пробная генерация |

## Настройки (Плагины → Codex image (GPT Image))

- **Подключение:** адрес API (`/v1`), API-ключ (хранится в хранилище учётных данных Harness, не в настройках), имя ссылки на ключ. По умолчанию `CLI_PROXY_API_KEY` — тот же ключ, что у провайдера CLIProxy в «Моделях», поэтому вводить его заново не нужно.
- **Модель:** модель генерации (по умолчанию `gpt-image-2.5`) и отдельная модель редактирования (необязательно). Кнопка «Проверить подключение» читает `/models` без траты генерации и подставляет список в подсказки.
- **Параметры генерации:** размер (авто, 1:1, 3:2, 2:3, 16:9, 9:16, 2048² или свой), подсказка формата в промпте, качество, фон (в т. ч. прозрачный), формат файла и сжатие, модерация, число вариантов за вызов (1–4), стиль по умолчанию, который дописывается к каждому промпту.
- **Сохранение и ожидание:** сохранять ли оригиналы в рабочую папку сессии, папка (по умолчанию `generated-images`), таймаут запроса.
- **Проверка:** пробная генерация по своему промпту с сохранёнными настройками.

Поля сохраняются кнопкой «Сохранить» в `cordis.patch.yml` профиля через штатный редактор конфигурации и применяются сразу, без перезапуска (все поля `volatile`). Значение, равное значению по умолчанию, снимает переопределение.

Агент может переопределить в одном вызове `size`, `quality`, `background`, `output_format` и `count`; остальное берётся из настроек.

## Особенности Codex-ретранслятора (проверено на `spa.brianfox.ru`)

- На запрос всегда возвращается **одно** изображение, `n` игнорируется. Поэтому несколько вариантов — это параллельные запросы; если часть из них не удалась, остальные всё равно возвращаются.
- `size` воспринимается как пожелание: без подсказки `1024x1024` приходил как `1536x1024`. С включённой «подсказкой формата» плагин дописывает в промпт соотношение сторон, и квадрат приходит квадратом (`1254x1254`).
- `output_format` и `output_compression` ретранслятор может проигнорировать и вернуть PNG — плагин сохраняет фактический формат.
- `background: transparent` работает (PNG с альфа-каналом).
- `/images/edits` принимает multipart с одним или несколькими изображениями (`image` / `image[]`).
- Генерация занимает 10–25 с при низком качестве, дольше при высоком.

## Безопасность

- Ключ не попадает в исходники, настройки, URL, браузер и результаты инструментов; в сообщениях об ошибках ключи и `Bearer` маскируются.
- Локальные маршруты `/api/codex-image/check` и `/api/codex-image/preview` идут через аутентифицированный мост Harness, принимают только JSON с заголовком `x-codex-image: 1` и тем же Origin.
- Файлы сохраняются только внутри рабочей папки сессии; пути `source_paths` для редактирования проверяются и по тексту, и по реальному пути (без выхода через `..` или ссылки).

## Разработка

```sh
npm run check   # node --check всех модулей
npm test        # node --test test/*.test.mjs
```

Тесты покрывают разбор настроек и аргументов, размеры и подсказку формата, multipart для правки, разбор ответа (b64 / data-URL / URL), ошибки с маскировкой ключа, частичные отказы вариантов, таймауты, поиск исходных изображений в диалоге и компиляцию схем инструментов.
